# 치이카와 런 · 모몽가의 작은 도주 (팬메이드 프로토타입)

횡스크롤 러너 게임입니다. 주인공은 화면 중앙에 고정되어 왼쪽에서 오른쪽으로 달리고, 음식을 먹어 체력(달리기 수치)을 유지하며, 점프·2단점프·앉기로 장애물과 구덩이를 피합니다. 추격자는 화면에 항상 보이지 않고 하단 거리 바로 표시됩니다. 로그인, 광고, 결제, 설정, 상점은 없습니다.

이 게임은 공식이 아닌 팬메이드 작품이며, 치이카와의 캐릭터와 세계관에 대한 권리는 원작자에게 있습니다. 캐릭터와 음식 그림은 이미지 생성 AI를 사용해 만든 파생 이미지이고, 출처 목록(manifest)은 구현 담당(코덱스)이 관리합니다. 공개·배포 전에 권리자의 허가 여부를 확인해야 하며, 이 README는 허가 상태를 확인하지 않았습니다.

기술: Phaser 4.2.1 + TypeScript + Vite. 게임 규칙은 `src/model.ts`(Phaser 의존 없음)에 있고, `src/main.ts`는 그리기와 입력을 담당합니다. 홈 화면과 게임 화면은 `index.html`, `src/style.css`입니다.

## 실행

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # 타입 검사 + 빌드
npm test         # 모델 테스트, 의존성 설치 없이 실행 가능 (Node 24)
```

`npm test`는 `node --experimental-strip-types --test tests/*.test.ts`를 실행합니다(모델·코스, 2층 코스 `tests/two-level.test.ts`, 화면 연출, 실주행 봇).

## 조작

| 동작 | 키보드 | 터치 |
|---|---|---|
| 점프(짧게 누르면 낮게, 길게 누르면 높게) / 2단점프(놓았다가 공중에서 다시 누르기) | Space / ↑ | 점프 버튼 |
| 앉기(누르고 있기) | ↓ | 앉기 버튼(누르고 있기) |
| 윗길에서 아래로 내려가기(앉은 채 점프: 그 가지를 통과해 내려감, 벌점 없음) | ↓ 누른 채 Space / ↑ | 앉기 버튼을 누른 채 점프 버튼 |
| 일시정지 / 계속 | P / Esc | 일시정지 버튼 |

탭이 가려지거나 기기를 회전하면 자동으로 일시정지됩니다. 조작 설명은 홈 화면에만 있고, 게임 화면에는 캐릭터 위 안내 문구와 장애물 라벨을 두지 않는 것이 사용자 요구입니다(구현은 코덱스 담당이라 이 README에서는 확인하지 않았습니다).

## 규칙 (시작값, 이후 튜닝 대상)

- 속도: 보통 6m/s, 탈진 4.2m/s, 가속 9m/s(×1.5). 추격자 6m/s.
- 추격자와의 거리(gap): 시작 30m, 최대 60m, 0 이하가 되면 잡힘.
- 체력 0~100, 초당 4 소모. 일반 음식 +20, 황금 음식 +25. 0이 되면 탈진이 되고 12 이상이 될 때까지 유지됩니다. 음식은 모두 12 이상이라 먹으면 항상 해제됩니다.
- 황금 음식: 보너스 점수, 1초 동안 가속(×1.5)과 무적. 다시 먹으면 1초로 갱신(중첩 없음). 무적 중에는 장애물 판정이 없고 장애물을 소비하지도 않습니다. 가속이 끝난 순간 장애물과 겹쳐 있으면 정상적으로 피격됩니다.
- 피격: 실제로 맞은 장애물만 소비됩니다. gap -3m, 0.5초 무적, 화면상 잠깐 뒤로 밀리는 표현(실제 distance는 후퇴하지 않음). 무적 중에 닿은 장애물은 소비되지 않으므로 무적이 끝났을 때 계속 겹쳐 있으면 바로 다시 피격됩니다.
- 장애물 폭은 생성할 때마다 범위 안에서 무작위입니다(`OBSTACLE_WIDTHS`, px): 블록 48~64, 타워 44~52, 낮고 긴 장애물 120~170, 구덩이 120~200, 빔 100~220.
  - 블록(점프), 빔(천장에 붙어 있어 점프로는 못 넘음, 앉으면 8px 여유), 타워(2단점프), 낮고 긴 장애물(2단점프를 늦게 눌러 체공을 늘려야 함), 구덩이.
  - 앉기를 놓으면 그 순간 일어나 빔에 바로 부딪힙니다(피격 1회, 같은 빔에 두 번 맞지 않음).
- 장애물: 첫 장애물은 19m, 이후 간격은 거리에 따라 22m에서 18m로 줄어듭니다(`difficultyAt`, 1200m에서 상한). 장애물은 140m 앞까지 미리 생성합니다. 6종 주기(블록 2·빔·타워·긴 장애물·구덩이)는 지상 슬롯 기준으로 그대로입니다. 단 2층 코스가 켜져 있으면 발판 진입 8m 전~하강 8m 뒤(+3m 여유) 구간의 지상 슬롯은 건너뛰고(주기 번호는 계속 증가), 그 대신 발판 위 장애물이 추가됩니다. 지상 슬롯 규칙 자체는 `{ platforms: false }`에서 그대로 확인합니다.
- 음식: 예정 위치(첫 7m, 이후 거리에 따라 24m에서 30m 간격)마다 ±4m 안에서 안전한 자리를 24번까지 찾고, 못 찾으면 그 음식은 건너뜁니다(안전 여유는 줄이지 않음). 음식끼리 8m 이상 떨어지고, 모든 위험 요소와는 가장자리 + 캐릭터 절반 폭 24 + 음식 절반 폭 16 + 4m 이상 떨어져 있습니다. 높이는 바닥에서 48~205px 사이 무작위이고 한 번의 점프로 닿습니다. 각 음식이 독립적으로 1/10 확률로 황금이 됩니다(시드 고정 난수).
- 구덩이: 캐릭터 중심이 구덩이 위에 있으면 지지가 없어 떨어집니다(가속 중에도 떨어집니다). 깊이 100px에서 0.9초 구출 포물선으로 구덩이 뒤 안전한 지점에 착지합니다. 보호 상태가 아니면 한 번 피격(gap -3)이고, 무적·가속 중이면 벌점이 없습니다. 구출 중에도 추격과 체력 소모는 계속되고 구출 중에는 무적이며, gap이 0이면 정상적으로 종료됩니다.
- 점프는 달리는 속도와 무관합니다: 이륙 속도 -760, 중력 1900이 항상 같아서 (끝까지 누른 점프의) 높이 약 152px(연속 수식 값; 1/120초 이산 적분으로 측정하면 약 149px), 체공 0.8초가 보통·탈진·가속 모두 같습니다(체력이 떨어져도 점프 상승·하강 속도가 그대로). 대신 수평 이동은 달리는 속도를 따르므로 탈진(4.2m/s) 점프는 보통(6m/s)보다 한 번에 가는 거리가 짧습니다. 그래서 탈진해도 통과할 수 있도록 장애물 폭 상한을 줄이고 탈진 속도를 4.2로 올렸습니다. 공중에서 속도 상태가 바뀌어도 점프 궤적은 달라지지 않습니다.
- 점프 높이: 첫 점프는 누르고 있는 동안 계속 오르고, 버튼을 놓으면 상승 속도를 -500으로 잘라 냅니다. 짧은 탭은 약 64px, 끝까지 누르면 약 149px입니다. 이 149px은 1/120초 이산 적분으로 실제 측정한 값이고 기존 연속 수식의 약 152px과 같은 물리입니다(최대로 누른 점프의 물리는 바뀌지 않았습니다). 2단점프는 기존처럼 고정 높이이고, 버튼을 계속 누르고 있어도 자동으로 2단점프하지 않습니다.
- 2층 코스(`platforms` 옵션, 기본 켜짐; `new RunnerModel(seed, true, { platforms: false })`로 끄면 기존 지상 코스 그대로): 80m부터 180m마다 발판이 하나씩 나오고 선택/필수가 번갈아 옵니다. 길이는 12·20·36m, 높이는 바닥에서 110px(발판 두께 16px)입니다. 발판은 아래에서 통과하고 위에서만 착지하며, 끝에서는 점프 입력 없이 떨어져 1층으로 내려옵니다(피격·구출 없음).
  - 필수 발판은 앞의 턱에 막혀 있어 짧은 탭으로는 오를 수 없고 길게 눌러야 합니다. 막히면 전진·거리가 멈추고 추격자는 6m/s로 다가오며 체력은 계속 줄지만 충돌 벌점(-3m)은 없습니다. 그 자리에서 다시 점프해 올라갈 수 있습니다. 황금 가속·무적도 턱을 통과하지 못합니다.
  - 발판 위에는 시작 3m 지점에 전용 음식이 있고(발판 위 80px), 선택 발판의 1층 쪽에는 음식이 없습니다. 20m 이상 발판에는 시작 10m 뒤에 장애물이 하나(블록·낮고 긴 장애물·빔) 있고, 12m 발판에는 없습니다. 지상 장애물은 발판 진입 8m 전과 하강 8m 뒤(+3m 여유) 안에 만들지 않습니다.
- NPC 조우와 레몬 스티커 미니게임: 코스에 200~300m 간격으로(첫 조우도 200~300m) 이름 없는 NPC가 서 있고, 같은 바닥(1층 또는 같은 발판)에서 땅에 서서(앉기·공중·피격 보호·막힘 아님) NPC 1.6m 이내에 들어가면 조우가 시작됩니다(`phase: 'minigame'`). 조우 위치는 장애물에서 가장자리+캐릭터 반폭+6m 떨어지고, 발판 경계 8m 안은 피하며 발판 위는 중앙 4m 안쪽에서만 만듭니다. 조우 일정은 장애물·음식 난수와 별도 난수로 만들어 `{ encounters: false }`로 끄면 장애물·음식·발판은 그대로입니다. 조우마다 독립 시드가 있고, 시드가 치이카와·하치와레·우사기 중 한 명을 같은 확률로 정합니다.
  - 미니게임(`src/sticker-game.ts`, 러너와 독립된 상태 기계): 캐릭터 선택 2초 → 안내(시간 제한 없음, `start()`를 기다림) → 5라운드(라운드당 2.8초, 화면 가운데 큰 레몬 위로 스티커(분홍 원)가 좌우로 오가고, 스티커 중심이 레몬(점선 원) 폭, 곧 이동 폭의 0.36~0.64 안일 때 `stamp()`하면 성공, 시간 초과는 실패, 판정 뒤 0.45초 피드백) → 결과(`continue()`를 기다림) → 3초 카운트 → `done`. 보상: 5개 성공 체력+40·1.5배·3초, 2~4개 +25·1.25배·2초, 0~1개 +10·1.1배·1초.
  - 조우 중에는 러너의 모든 시계(거리·체력·추격·가속·무적·피격 보호·경과 시간)가 멈추고 점프·앉기·일시정지·`start()`로 우회할 수 없습니다. `completeEncounter(id, 보상)`이 보상을 정확히 한 번 적용하고 게임을 다시 진행시킵니다. 체력은 100까지, 12 이상이 되면 탈진이 풀립니다. 이벤트 가속은 기본 속도 6m/s에 배수를 곱하고, 황금 가속(9m/s)과는 큰 쪽만 적용됩니다(겹쳐도 곱해지지 않음). 이벤트 가속에는 무적이 없습니다.
- 시드: 기본 시드는 13579이고, 같은 시드는 같은 코스입니다. 시작 화면은 고정 시드, 다시 시작하면 `Date.now()` 시드입니다.

## 범위

포함: 홈 화면, 한 화면 한 가지 모드, 시드 기반 반복 코스, HUD, 일시정지, 다시 시작, 로컬 최고 거리, 모몽가(주인공)·데카츠요(추격자)와 음식 그림(구현 담당이 생성).
제외: 소리, 캐릭터별 능력, 추격자 가속, PWA/앱 포장, 설정, 상점, 로그인, 광고, 결제.

## 실제로 검증한 것

`npm test` 115개(모델·지상 코스 46 + 2층 코스 `tests/two-level.test.ts` 28 + 스티커 미니게임 `tests/sticker-game.test.ts` 15 + NPC 조우 `tests/encounter.test.ts` 20 + 화면 연출 `tests/presentation.test.ts` 3 + 실주행 봇 `tests/endurance.test.ts` 3)가 모두 통과했습니다(Node 24.15.0). 게임과 같은 1/120초 고정 간격으로 `src/model.ts`를 구동하며, 빈 코스 옵션(`new RunnerModel(seed, false)`)과 시드 옵션을 사용합니다. 기존 지상 코스 계약은 `{ platforms: false }`로 2층과 분리해 검사합니다.

- 규칙 값 고정 확인(체력 4/20/25/12, 가속 1초·9m/s, gap -3, 보호 0.5초, 캐릭터 크기, 중력·점프 속도, 장애물 폭 범위, 음식 간격·여유·높이 상수), 시작 상태, ready 단계 무시
- 속도 상태 우선순위, 체력 소모, 탈진 유지(1~11에서도 유지), 탈진 중 gap이 1.8/s로 줄어 30m가 약 16.7초 뒤 잡힘, 음식 +20/황금 +25와 상한 100
- 황금: 보너스 30(상한에서 100), 1초 가속, 갱신(중첩 없음), 체력 0에서의 가속 후 탈진 해제와 다시 탈진되는 경계, gap +3/s와 상한 60
- 피격 -3 한 번, 0.5초 무적, 소비는 실제 피격에서만, distance 후퇴 없음, 무적 중 닿은 장애물이 무적 종료 직후 피격되는 것, 가속 중 무적과 종료 후 겹침 피격, gap 0이면 종료
- 일시정지 시 시간·거리·gap·체력·가속·무적·구출 정지, 입력 무시, 종료 상태에서는 시작 불가
- 점프 물리(높이 약 152px), 2단점프, 세 번째 입력 무시, 탈진 점프의 같은 높이·긴 체공, 공중 음식·가속 시작·종료에도 궤적 불변, 착지 후 초기화
- 앉기 높이 36, 빔 8px 여유, 서 있으면 피격, 앉으면 통과, 빔 아래에서 앉기를 놓으면 즉시 일어나 한 번만 피격, 빔은 어떤 점프 타이밍으로도 못 넘음

- 알려진 점: 음식이 거의 모든 예정 슬롯에 놓이게 되어(배치 100%) 음식을 전부 먹는다고 가정한 체력 수입이 초당 약 5.0으로 소모 4를 넘습니다. 그래서 그 가정의 상한 검사는 "소모의 2배 이하"로 완화했고(걷기만 하는 수입 1.7/s는 그대로 검사), 실제 균형은 root 입력 봇이 확인합니다(root 기록: 지상 132개 시드 전부 1000m·최저 체력 41.53, 상층 132개 시드 전부 1000m·착지 1177, 기본 mini 37시드 113회 완료, 피격·구출 겹침 0).

### v9 갱신 (아래 v8 기록과 구분; 이전 v8 줄은 당시 화면·테스트 수 기준)

- 미니게임 UI: 화살표·초록 막대를 없애고, 가운데 큰 레몬 하나가 주인공이며 그 위를 스티커가 움직입니다. 레몬 폭을 성공 구간(28%)에 맞췄고 점선 원으로 표시합니다. 5개 진행은 위의 작은 한 줄입니다. 판정 규칙(`cursor` 0.36~0.64)은 그대로입니다. 결과 화면에서는 우상단 일시정지·홈 버튼을, 복귀 카운트 동안에는 러너 HUD 버튼(일시정지·홈)을 숨깁니다(P·창 전환 일시정지와 가운데 계속하기는 유지). 계속하기·돌아가기 버튼은 가운데 정렬입니다.
- 가시덩굴 통로(root 모델): 2층 가지 중 일부(`gateX`)는 입구가 필수 점프이고 22m 뒤 덩굴이 위층 통로를 막아, 앉기+점프로 내려가야 합니다. 그림은 `obstacle-vines`로 그립니다. `tests/two-level.test.ts`의 위층 장애물 계약은 이 36m 가지(덩굴이 일반 장애물을 대신함)를 예외로 맞췄습니다.
- 통합 검증(root 기록, 8d2896a): `npm test` 123/123(root `tests/lane-switch.test.ts` 8개 포함), `npm run test:assets` 4/4, 타입 검사·`npm run build` 통과, diff 검사 이상 없음. 새 입력 봇 기록: 상층 코스 132개 시드에서 상층 착지 1208회·1000m 완주, 기본 코스(2층+조우+미니게임) 37개 시드 109회 주행에서 조우 입장·5라운드·세 보상 등급 포함. 이 줄의 수치는 v9 기준이고, 아래 v8·초기 단계의 115개·9c5d0f5 같은 숫자는 당시 기록입니다.
- 브라우저 스모크(Claude, headless Chrome 1280×720, 위치 이동·체력 유지 같은 QA 보조 사용, 마우스·키보드 이벤트): 레몬 위 스티커·점선 원 정렬, 5라운드→결과(우상단 버튼 없음)→카운트(러너 HUD 버튼 없음)→재개, 덩굴 그리기(가지에서 위쪽까지). 실제 키 입력으로 상층 가지에서 앉기+Space 하강(바닥 460 착지, 피격 0, 구출 없음), ↓와 Space를 같은 프레임에 보내도 즉시 하강, 덩굴 앞에서 거의 멈춘 뒤 같은 자리에서 하강하면 덩굴 아래 통과, ↑ 누른 채 유지는 일반 상승만(점프 1회, 자동 2단점프 없음). 콘솔 오류 없음. 범위 밖: 앉기·점프 버튼 동시 포인터와 실기기 터치, 사람 손 체감 난이도, 이번 최종 빌드의 세로·가로 모바일 화면 재확인은 하지 못했습니다.

### 장애물별 통과 가능한 타이밍 창 (모델에서 측정)

점프 시작 시점을 0.04m 간격으로 훑고, 2단점프는 첫 점프 후 0.1~1.2초 사이의 입력 시점을 모두 탐색했습니다. 최대 폭이 가장 어려운 경우입니다. 가속 상태는 블록·타워·긴 장애물에 무적이라 측정하지 않았습니다. 탈진 상태의 최적 입력 시점이 탐색 상한(1.2초)에 걸려 있어 실제 창은 더 넓을 수 있습니다.

### 알려진 점 (버그 아님, 튜닝 후보)

- 이전 초당 3 소모 버전의 브라우저(headless Chrome)에서는 입력 없이 달릴 때 약 33초 근처의 탈진 감속을 화면 거리 숫자로 확인했습니다. 현재 초당 4 버전은 음식을 먹지 않으면 25초에 탈진하며 이 경계는 모델 테스트로 확인했습니다. 이번 변경의 브라우저 시간 측정과 실기기 터치는 하지 않았습니다.

- 장애물 사이의 빈 거리는 처음 두 개 사이가 약 18.9m, 이후 최소 약 13.8m(상한 18m 간격, 1200m 이후)입니다. 보통 속도로 약 2.3초, 가속 중에는 약 1.5초입니다. 음식은 안전하지 않은 슬롯을 건너뛰어서(약 16%) 400m 이전 약 3.1개/100m, 1600~2000m 약 2.9개/100m입니다(모두 먹으면 수입 약 3.8/s → 3.6/s, 소모 4/s, 걸어서 먹을 수 있는 음식만 먹으면 약 1.5/s). 완화한 뒤에도 음식을 절반만 먹으면 체력이 부족하므로 실제 플레이로 본 추가 튜닝 후보입니다.
- 그림 용량: 기존 러너는 `game-atlas.webp`(2048×1024, 17프레임, 937,292바이트), 미니게임과 모브는 `event-atlas.webp`(1024×256, 5프레임, 133,868바이트)를 사용하며 시트마다 JSON이 있습니다. 홈 그림 5장은 합 335,688바이트입니다. 원본 PNG는 배포 폴더 밖에 보존되고 게임은 이 PNG를 내려받지 않습니다. 이전 단계의 'atlas 1장만 요청' 기록은 미니게임 추가 전입니다. 현재 브라우저 스모크에서 404·콘솔 오류는 없었습니다(실제 기기 터치·FPS는 미확인).
- 참고 영상은 35초 구간만 직접 확인했고(자동 자막만 있음, 이후 구간은 재생 오류), 새 데카츠요 그림과의 세부 일치는 사람이 눈으로 확인해야 합니다.
- 장애물 그림을 폭×높이에 맞춰 늘려 그려서 비율이 달라집니다. 바위는 타워에서 가늘고 길게(원본 약 1.8:1이 약 0.3:1), 앉은 모몽가는 납작하게(원본 약 1.2:1이 약 2.8:1) 보입니다. 충돌 판정은 영향이 없습니다.
- 모바일 세로 화면에서는 게임 화면이 약 360×200px로 작습니다. 바(양끝 이미지)와 버튼은 하단 띠 안에 들어가지만 화면 자체는 작습니다. 가로 화면이 기본 권장입니다.
- 그림과 에셋을 `/assets/...` 절대 경로로 불러오므로, 앱 포장(Capacitor 등)에서 기본 경로를 바꾸면 경로 조정이 필요합니다.
- 장애물 폭이 커져도 블록 64의 보통 속도 단일 점프 창은 0.18초, 타워 64의 보통 속도 2단점프 창은 0.25초로 통과 가능합니다.

### UI v3·v4 브라우저 확인 (headless Chrome, 실제 그림)

체력 숫자와 추격 거리 수치(gap 숫자·힌트) DOM이 없음(HUD의 "달린 거리" 숫자는 의도적으로 남아 있음), 일시정지 버튼의 `paused` 클래스와 `aria-label` 전환, 플레이 중 `is-running` 클래스, 점프 버튼 `held` 클래스(앉기와 동일 스타일), 홈↔게임 전환, 게임 중 이미지 요청이 atlas 1장+json뿐임, 콘솔 오류·404 없음을 확인했습니다. 홈의 데카츠요가 모몽가보다 크고 음식은 푸딩·황금 슈크림 2개가 겹치지 않으며, HUD는 우측 상단에 버튼 아래 거리 카드 순서입니다. 시작 시 몬스터가 왼쪽 화면 일부를 채웁니다. 모바일 세로·가로에서 추격 바와 버튼은 캐릭터를 가리지 않았습니다. v4: 추격 바는 왼쪽 데카츠요 고정, 모몽가 이미지가 marker로 이동(8~92%), 점프 버튼 `held`가 손을 뗄 때 해제됨, 홈에서 황금 슈크림이 위로·모몽가가 바닥 위로·데카츠요가 더 크고 gap 칩과 터치 문구가 없음을 확인했습니다. 연출은 flat 2D(바닥 타원 그림자만)이며 몬스터는 420x280px입니다. 추격 바 이미지의 ±5° 흔들림은 CSS 코드로만 확인했고 움직임을 눈으로 본 것은 아닙니다.

모브 NPC는 눈·입·코·볼 표시가 없는 회색 얼굴을 사용합니다. 게임용 event-atlas.webp는 133,868바이트입니다.

## 검증하지 못한 것

- 실제 기기의 터치 입력(점프·앉기 버튼을 손으로 누르는 동작), 일반 브라우저 창에서의 사람 손 조작 느낌, 프레임 속도와 성능. headless Chrome에서 키 입력과 화면 크기 에뮬레이션만 확인했고 터치 이벤트는 보내지 않았습니다.
- 실제 사람이 플레이했을 때의 재미와 난이도. 위 수치는 시작값입니다.
- 세로 화면 배치와 작은 화면에서의 반응 시간.
- 현재 초당 4 버전에서 모든 코스의 1000m 완주를 보장하지 않습니다. 입력 봇은 최초 탈진 또는 1000m까지만 검사했으며, 탈진 이후 주행과 3000m 완주의 공정성은 검증하지 않았습니다.
- 치이카와 캐릭터를 공개 앱에 쓸 수 있는지(권리자 허가).

### 게임 시작 영상

시작 버튼을 처음 누르면 제공된 시작 영상(720p, 약 1.1 MB)을 재생한 뒤 게임을 시작합니다. 건너뛰기 버튼이나 Esc로 바로 시작할 수 있고, 같은 페이지에서 재도전할 때는 영상을 반복하지 않습니다. 영상 재생 중에는 게임 시간이 흐르지 않습니다. 다른 탭으로 이동하면 영상을 멈추며, 재생이 차단되면 계속 보기 버튼을 표시합니다.

### 출발 준비와 동전

- 시작 영상 종료·건너뛰기 뒤 게임 이미지 로딩을 마치고 3초 준비 카운트다운 후 달립니다. 재도전에도 준비 시간을 제공합니다. 준비 중 탭을 벗어나면 멈추며 버튼으로 계속할 수 있습니다.
- 첫 30m에는 일반·황금 음식이 나오지 않습니다.
- 동전은 장애물과 음식에서 떨어진 안전한 구간에 1~5개 묶음으로 나옵니다. 묶음 사이에는 공백이 있습니다.
- 은색 동전 +1, 금색 동전 +3. 체력·속도·추격 거리에 효과는 없으며 이번 판 수량을 HUD와 결과에 표시합니다. 새 판은 0부터 시작합니다.
- 계정별 누적, 저장, 치장 아이템과 상점은 아직 구현하지 않았습니다.
- 은색·금색 동전은 같은 애니메이션 그림체의 12방향 시트(프레임 128×128)를 사용해 수직축 기준으로 360도 회전합니다. 초당 10프레임, 한 바퀴 약 1.2초이며 일시정지하면 회전도 멈춥니다.

### 등장 간격과 스티커 난이도

- 미니게임 NPC 주변 8m에는 음식과 동전을 배치하지 않습니다. NPC와 장애물도 기존 6m 이상의 안전 여유를 유지합니다.
- 동전은 음식에서 최소 5m, 장애물에서 최소 4m 떨어뜨립니다(이미지 너비를 제외한 간격). 따라서 통나무 위·덩굴 아래에서 동전과 장애물을 동시에 처리하는 배치는 사용하지 않습니다.
- 종류가 한곳에 몰리지 않게 분리하는 규칙이며, 화면 전체를 한 종류로만 제한하는 방식은 아닙니다.
- 레몬 스티커 5라운드는 라운드마다 속도가 조금씩 증가합니다. 제한 시간과 판정 영역·보상은 유지하고, 최고 속도는 초당 0.88왕복으로 제한합니다.
