# 도형 추격 러너 (프로토타입 v2)

도형만 쓰는 횡스크롤 러너 프로토타입입니다. 주인공은 화면 중앙에 고정되어 왼쪽에서 오른쪽으로 달리고, 음식을 먹어 체력(달리기 수치)을 유지하며, 점프·2단점프·앉기로 장애물과 구덩이를 피합니다. 추격자는 화면에 항상 보이지 않고 하단 거리 바로 표시됩니다. 규칙 검증용 프로토타입이라 캐릭터 그림, 소리, 로그인, 광고, 결제는 없습니다.

기술: Phaser 4.2.1 + TypeScript + Vite. 게임 규칙은 `src/model.ts`(Phaser 의존 없음)에 있고, `src/main.ts`는 그리기와 입력을 담당합니다.

## 실행

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # 타입 검사 + 빌드
npm test         # 모델 테스트, 의존성 설치 없이 실행 가능 (Node 24)
```

`npm test`는 `node --experimental-strip-types --test tests/model.test.ts`를 실행합니다.

## 조작

| 동작 | 키보드 | 터치 |
|---|---|---|
| 점프 / 2단점프(공중에서 한 번 더) | Space / ↑ | 점프 버튼 |
| 앉기(누르고 있기) | ↓ | 앉기 버튼(누르고 있기) |
| 일시정지 / 계속 | P / Esc | 일시정지 버튼 |

탭이 가려지거나 기기를 회전하면 자동으로 일시정지됩니다.

## v2 규칙 (시작값, 이후 튜닝 대상)

- 속도: 보통 6m/s, 탈진 3.6m/s, 가속 9m/s(×1.5). 추격자 6m/s.
- 추격자와의 거리(gap): 시작 30m, 최대 60m, 0 이하가 되면 잡힘.
- 체력 0~100, 초당 3 소모. 일반 음식 +16, 황금 음식 +20. 0이 되면 탈진이 되고 12 이상이 될 때까지 유지됩니다. 음식은 모두 12 이상이라 먹으면 항상 해제됩니다.
- 음식은 24m마다 1개이고, 각 음식이 독립적으로 1/15 확률로 황금이 됩니다(시드 고정 난수). 시작 화면은 고정 시드, 다시 시작하면 `Date.now()` 시드입니다.
- 황금 음식: 보너스 점수, 1초 동안 가속(×1.5)과 무적. 다시 먹으면 1초로 갱신(중첩 없음). 무적 중에는 장애물 판정이 없고 장애물을 소비하지도 않습니다. 가속이 끝난 순간 장애물과 겹쳐 있으면 정상적으로 피격됩니다.
- 피격: 실제로 맞은 장애물만 소비됩니다. gap -3m, 0.5초 무적, 화면상 잠깐 뒤로 밀리는 표현(실제 distance는 후퇴하지 않음). 무적 중에 닿은 장애물은 소비되지 않으므로 무적이 끝났을 때 계속 겹쳐 있으면 바로 다시 피격됩니다.
- 장애물: 블록(점프), 빔(앉기, 천장에 붙어 있어 점프로는 못 넘음, 앉으면 8px 여유), 타워(2단점프), 낮고 긴 장애물 160/185/210(2단점프를 늦게 눌러 체공을 늘려야 함), 구덩이 140/180/220.
- 구덩이: 캐릭터 중심이 구덩이 위에 있으면 지지가 없어 떨어집니다(가속 중에도 떨어집니다). 깊이 100px에서 0.9초 구출 포물선으로 구덩이 뒤 안전한 지점에 착지합니다. 보호 상태가 아니면 한 번 피격(gap -3)이고, 무적·가속 중이면 벌점이 없습니다. 구출 중에도 추격과 체력 소모는 계속되고 구출 중에는 무적이며, gap이 0이면 정상적으로 종료됩니다.
- 탈진 중 점프: 이륙 시 속도 비율(3.6/6 = 0.6)로 점프 속도와 중력을 함께 조절해 같은 높이와 수평 이동 거리를 유지하고 체공만 늘립니다. 이 값은 이륙할 때 고정되어 공중에서 바뀌지 않고 착지 또는 다음 점프에서만 갱신됩니다.

## 범위

포함: 한 화면, 한 가지 모드, 도형, 시드 기반 반복 코스, HUD, 일시정지, 다시 시작, 로컬 최고 거리.
제외: 그림, 소리, 캐릭터와 능력, 미니게임, 추격자 가속, PWA/앱 포장, 제3자 IP 사용.

## 실제로 검증한 것

`tests/model.test.ts` 38개가 모두 통과했습니다(Node 24.15.0). 게임과 같은 1/120초 고정 간격으로 `src/model.ts`를 구동하며, 빈 코스 옵션(`new RunnerModel(seed, false)`)과 시드 옵션을 사용합니다.

- 규칙 값 고정 확인(체력 3/16/20/12, 가속 1초·9m/s, gap -3, 보호 0.5초, 캐릭터 크기, 중력·점프 속도), 시작 상태, ready 단계 무시
- 속도 상태 우선순위, 체력 소모, 탈진 유지(1~11에서도 유지), 12.5초 뒤 잡힘, 음식 +16/황금 +20와 상한 100
- 황금: 보너스 30(상한에서 100), 1초 가속, 갱신(중첩 없음), 체력 0에서의 가속 후 탈진 해제와 다시 탈진되는 경계, gap +3/s와 상한 60
- 피격 -3 한 번, 0.5초 무적, 소비는 실제 피격에서만, distance 후퇴 없음, 무적 중 닿은 장애물이 무적 종료 직후 피격되는 것, 가속 중 무적과 종료 후 겹침 피격, gap 0이면 종료
- 일시정지 시 시간·거리·gap·체력·가속·무적·구출 정지, 입력 무시, 종료 상태에서는 시작 불가
- 점프 물리(높이 약 152px), 2단점프, 세 번째 입력 무시, 탈진 점프의 같은 높이·긴 체공, 공중 음식·가속 시작·종료에도 궤적 불변, 착지 후 초기화
- 앉기 높이 36, 빔 8px 여유, 서 있으면 피격·앉으면 통과·빔 아래에서 놓아도 안전, 빔은 어떤 점프 타이밍으로도 못 넘음
- 구덩이: 낙하와 한 번 피격, 0.9초 구출, 구덩이 뒤 안전 착지(3개 폭 × 3개 상태 × 인접 장애물·간격 조합 540건에서 장애물 안에 착지하지 않음), 보호·가속 중 벌점 없음, 구출 중 무적·입력 무시, 연속 구덩이에서 구출 반복 없음, gap 0 종료
- 시드: 같은 시드는 같은 코스, 다른 시드는 다른 코스, 음식 1만 개 분포(시드 3개에서 황금 비율 1/15 ± 0.75%p, 황금 다음에 황금이 나올 확률도 1/15 근처), 음식 24m 간격, 장애물 종류·폭이 모두 나옴, 장애물 사이 빈 거리 약 10m 이상
- 같은 시드·같은 입력이면 같은 결과(결정성)
- 코덱스가 통합 상태 `e3c8c82`에서 타입 검사와 production build(`npm run build`)를 직접 실행해 통과를 확인했습니다(제가 직접 실행한 것은 아님).

### 장애물별 통과 가능한 타이밍 창 (모델에서 측정)

점프 시작 시점을 0.04m 간격으로 훑고, 2단점프는 첫 점프 후 0.1~1.2초 사이의 입력 시점을 모두 탐색한 결과입니다. 가속 상태는 블록·타워·긴 장애물에 무적이라 측정하지 않았습니다. 탈진 상태의 최적 입력 시점이 탐색 상한(1.2초)에 걸려 있어 실제 창은 더 넓을 수 있습니다.

| 장애물 | 보통 단일 | 보통 2단 | 탈진 단일 | 탈진 2단 |
|---|---|---|---|---|
| 블록 60 | 0.20초 | 0.96초 | 0.32초 | 1.63초 |
| 블록 80 | **0.11초** | 0.87초 | 0.20초 | 1.51초 |
| 타워 60 | 불가 | 0.27초 | 불가 | 0.46초 |
| 긴 160 | 불가 | 0.66초 | 불가 | 1.12초 |
| 긴 185 | 불가 | 0.57초 | 불가 | 0.97초 |
| 긴 210 | 불가 | 0.47초 | 불가 | 0.80초 |
| 구덩이 140 | 0.53초 | 1.33초 | 0.81초 | 2.11초 |
| 구덩이 180 | 0.45초 | 1.26초 | 0.56초 | 1.86초 |
| 구덩이 220 | 0.30초 | 1.09초 | 0.31초 | 1.61초 |

가속 상태의 구덩이는 단일 0.52~0.63초, 2단 0.98초로 모두 통과 가능했습니다.

### 알려진 점 (버그 아님, 튜닝 후보)

- 블록 80은 보통 속도에서 한 번 점프로 넘길 수 있는 타이밍이 약 0.11초로 가장 빡빡합니다(2단점프는 0.87초). 60폭 블록은 0.20초입니다.
- 음식의 약 83%(602개 중 502개)가 지면에 있고, 모두 먹으면 초당 약 3.4로 소모(3)보다 많지만 75%만 먹으면 약 2.55로 소모보다 적습니다.
- 장애물 사이의 빈 거리는 최소 약 10m(보통 속도에서 1.7초, 탈진 속도에서 2.8초)입니다.

## 검증하지 못한 것

- 실제 브라우저에서의 화면 그리기, 입력, HUD, 터치 버튼, 구출·밀림 연출. 브라우저 도구를 쓸 수 없어(재시도에서도 host unavailable) 모델만 테스트했고 `src/main.ts`는 테스트하지 않았습니다.
- 실제 사람이 플레이했을 때의 재미와 난이도. 위 수치는 시작값입니다.
- 세로 화면 배치와 작은 화면에서의 반응 시간.
- 스크립트 봇으로 3000m를 완주하는 코스 공정성 검사는 범위 밖으로 두었습니다.
- 치이카와 캐릭터를 공개 앱에 쓸 수 있는지. 이 프로토타입은 해당 자료를 쓰지 않습니다.
