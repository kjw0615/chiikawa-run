# 치이카와 런 · 모몽가의 작은 도주 (팬메이드 프로토타입)

횡스크롤 러너 게임입니다. 주인공은 화면 중앙에 고정되어 왼쪽에서 오른쪽으로 달리고, 음식을 먹어 체력(달리기 수치)을 유지하며, 점프·2단점프·앉기로 장애물과 구덩이를 피합니다. 추격자는 화면에 항상 보이지 않고 하단 거리 바로 표시됩니다. 로그인, 광고, 결제, 설정, 상점은 없습니다.

이 게임은 공식이 아닌 팬메이드 작품이며, 치이카와의 캐릭터와 세계관에 대한 권리는 원작자에게 있습니다. 캐릭터와 음식 그림은 이미지 생성 AI를 사용해 만든 파생 이미지이고, 출처 목록(manifest)은 구현 담당(코덱스)이 관리합니다. 공개·배포 전에 권리자의 허가 여부를 확인해야 하며, 이 README는 허가 상태를 확인하지 않았습니다.

기술: Phaser 4.2.1 + TypeScript + Vite. 게임 규칙은 `src/model.ts`(Phaser 의존 없음)에 있고, `src/main.ts`는 그리기와 입력을 담당합니다. 홈 화면과 게임 화면은 `index.html`, `src/style.css`입니다.

## 실행

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # 타입 검사 + 빌드
npm test         # 모델 테스트, 의존성 설치 없이 실행 가능 (Node 24)
```

`npm test`는 `node --experimental-strip-types --test tests/model.test.ts`를 실행합니다.

## 조작

| 동작 | 키보드 | 터치 |
|---|---|---|
| 점프 / 2단점프(공중에서 한 번 더) | Space / ↑ | 점프 버튼 |
| 앉기(누르고 있기) | ↓ | 앉기 버튼(누르고 있기) |
| 일시정지 / 계속 | P / Esc | 일시정지 버튼 |

탭이 가려지거나 기기를 회전하면 자동으로 일시정지됩니다. 조작 설명은 홈 화면에만 있고, 게임 화면에는 캐릭터 위 안내 문구와 장애물 라벨을 두지 않는 것이 사용자 요구입니다(구현은 코덱스 담당이라 이 README에서는 확인하지 않았습니다).

## 규칙 (시작값, 이후 튜닝 대상)

- 속도: 보통 6m/s, 탈진 3.6m/s, 가속 9m/s(×1.5). 추격자 6m/s.
- 추격자와의 거리(gap): 시작 30m, 최대 60m, 0 이하가 되면 잡힘.
- 체력 0~100, 초당 4.5 소모. 일반 음식 +16, 황금 음식 +20. 0이 되면 탈진이 되고 12 이상이 될 때까지 유지됩니다. 음식은 모두 12 이상이라 먹으면 항상 해제됩니다.
- 황금 음식: 보너스 점수, 1초 동안 가속(×1.5)과 무적. 다시 먹으면 1초로 갱신(중첩 없음). 무적 중에는 장애물 판정이 없고 장애물을 소비하지도 않습니다. 가속이 끝난 순간 장애물과 겹쳐 있으면 정상적으로 피격됩니다.
- 피격: 실제로 맞은 장애물만 소비됩니다. gap -3m, 0.5초 무적, 화면상 잠깐 뒤로 밀리는 표현(실제 distance는 후퇴하지 않음). 무적 중에 닿은 장애물은 소비되지 않으므로 무적이 끝났을 때 계속 겹쳐 있으면 바로 다시 피격됩니다.
- 장애물 폭은 생성할 때마다 범위 안에서 무작위입니다(`OBSTACLE_WIDTHS`, px): 블록 48~64, 타워 48~64, 낮고 긴 장애물 140~210, 구덩이 120~220, 빔 100~220.
  - 블록(점프), 빔(천장에 붙어 있어 점프로는 못 넘음, 앉으면 8px 여유), 타워(2단점프), 낮고 긴 장애물(2단점프를 늦게 눌러 체공을 늘려야 함), 구덩이.
  - 앉기를 놓으면 그 순간 일어나 빔에 바로 부딪힙니다(피격 1회, 같은 빔에 두 번 맞지 않음).
- 장애물: 첫 장애물은 19m, 이후 간격은 거리에 따라 22m에서 18m로 줄어듭니다(`difficultyAt`, 1200m에서 상한). 장애물은 140m 앞까지 미리 생성합니다. 6종 주기(블록 2·빔·타워·긴 장애물·구덩이)는 그대로입니다.
- 음식: 예정 위치(첫 7m, 이후 거리에 따라 30m에서 42m 간격)마다 ±4m 안에서 안전한 자리를 24번까지 찾고, 못 찾으면 그 음식은 건너뜁니다(안전 여유는 줄이지 않음). 음식끼리 8m 이상 떨어지고, 모든 위험 요소와는 가장자리 + 캐릭터 절반 폭 24 + 음식 절반 폭 16 + 4m 이상 떨어져 있습니다. 높이는 바닥에서 48~205px 사이 무작위이고 한 번의 점프로 닿습니다. 각 음식이 독립적으로 1/10 확률로 황금이 됩니다(시드 고정 난수).
- 구덩이: 캐릭터 중심이 구덩이 위에 있으면 지지가 없어 떨어집니다(가속 중에도 떨어집니다). 깊이 100px에서 0.9초 구출 포물선으로 구덩이 뒤 안전한 지점에 착지합니다. 보호 상태가 아니면 한 번 피격(gap -3)이고, 무적·가속 중이면 벌점이 없습니다. 구출 중에도 추격과 체력 소모는 계속되고 구출 중에는 무적이며, gap이 0이면 정상적으로 종료됩니다.
- 탈진 중 점프: 이륙 시 속도 비율(3.6/6 = 0.6)로 점프 속도와 중력을 함께 조절해 같은 높이와 수평 이동 거리를 유지하고 체공만 늘립니다. 이 값은 이륙할 때 고정되어 공중에서 바뀌지 않고 착지 또는 다음 점프에서만 갱신됩니다.
- 시드: 기본 시드는 13579이고, 같은 시드는 같은 코스입니다. 시작 화면은 고정 시드, 다시 시작하면 `Date.now()` 시드입니다.

## 범위

포함: 홈 화면, 한 화면 한 가지 모드, 시드 기반 반복 코스, HUD, 일시정지, 다시 시작, 로컬 최고 거리, 모몽가(주인공)·데카츠요(추격자)와 음식 그림(구현 담당이 생성).
제외: 소리, 캐릭터별 능력, 미니게임, 추격자 가속, PWA/앱 포장, 설정, 상점, 로그인, 광고, 결제.

## 실제로 검증한 것

`npm test` 48개(모델·코스 46 + 화면 연출 `tests/presentation.test.ts` 2 + 추가 연출 검증)가 모두 통과했습니다(Node 24.15.0). 게임과 같은 1/120초 고정 간격으로 `src/model.ts`를 구동하며, 빈 코스 옵션(`new RunnerModel(seed, false)`)과 시드 옵션을 사용합니다.

- 규칙 값 고정 확인(체력 3/16/20/12, 가속 1초·9m/s, gap -3, 보호 0.5초, 캐릭터 크기, 중력·점프 속도, 장애물 폭 범위, 음식 간격·여유·높이 상수), 시작 상태, ready 단계 무시
- 속도 상태 우선순위, 체력 소모, 탈진 유지(1~11에서도 유지), 12.5초 뒤 잡힘, 음식 +16/황금 +20와 상한 100
- 황금: 보너스 30(상한에서 100), 1초 가속, 갱신(중첩 없음), 체력 0에서의 가속 후 탈진 해제와 다시 탈진되는 경계, gap +3/s와 상한 60
- 피격 -3 한 번, 0.5초 무적, 소비는 실제 피격에서만, distance 후퇴 없음, 무적 중 닿은 장애물이 무적 종료 직후 피격되는 것, 가속 중 무적과 종료 후 겹침 피격, gap 0이면 종료
- 일시정지 시 시간·거리·gap·체력·가속·무적·구출 정지, 입력 무시, 종료 상태에서는 시작 불가
- 점프 물리(높이 약 152px), 2단점프, 세 번째 입력 무시, 탈진 점프의 같은 높이·긴 체공, 공중 음식·가속 시작·종료에도 궤적 불변, 착지 후 초기화
- 앉기 높이 36, 빔 8px 여유, 서 있으면 피격, 앉으면 통과, 빔 아래에서 앉기를 놓으면 즉시 일어나 한 번만 피격, 빔은 어떤 점프 타이밍으로도 못 넘음
- 구덩이: 낙하와 한 번 피격, 0.9초 구출, 구덩이 뒤 안전 착지(새 폭 범위 3종 × 3개 상태 × 인접 장애물·간격 조합 540건에서 장애물 안에 착지하지 않음), 보호·가속 중 벌점 없음, 구출 중 무적·입력 무시, 연속 구덩이에서 구출 반복 없음, gap 0 종료
- 새 코스 계약(시드 8개): `difficultyAt` 값(0m 22/30, 600m 20/36, 1200m 이상 18/42), 첫 장애물 19m와 간격 진행, 장애물 140m 앞 생성, 음식은 예정 위치 ±4m·간격 8m 이상·첫 음식 3~11m(시드 8개 4만m에서 예정 위치의 약 20%가 안전 때문에 건너뛰어짐), 모든 음식과 모든 위험 요소의 거리가 가장자리 + 24 + 16 + 4m 이상, 음식 높이 48~205px(평균 약 126px), 장애물 폭 범위, 종류 비율 6구간 주기, 첫 장애물은 블록
- 음식 도달: 바닥 높이 음식은 걸어서 먹고, 114px 이상은 걸어서는 못 먹고 점프로 먹으며, 48~205px 전 구간이 보통·탈진 상태에서 한 번 점프로 닿음(여러 타이밍)
- 시드 3개의 황금 비율이 1/10 ± 0.75%p, 황금 다음에 황금이 나올 확률도 1/10 근처
- 같은 시드·같은 입력이면 같은 결과(결정성)
- 통합 확인: 소모 4.5/s·황금 10% 반영 후 `claude/runner-ui-v3`(UI `3a518b5` + 모델 `0b7517e` + 코덱스 모션 `6185565` 병합)에서 `npm test` 46/46, `npm run test:assets` 2/2, `npm run build`(타입 검사 포함)를 직접 실행해 통과를 확인했습니다. 코덱스도 통합 preview에서 같은 결과를 보고했습니다.
- (이전 단계 기록: UI v2·atlas 1024x512 시절. 최신 확인은 아래 UI v3 절) 실제 그림을 넣은 상태를 headless Chrome(DevTools 프로토콜로 클릭·키 입력·화면 저장)으로 확인했습니다. 홈 화면의 그림 5장 로딩과 렌더, 홈에서 게임 화면으로 전환과 캔버스 크기, 시작 후 달리기(거리·체력·gap 변화), 점프·앉기 키 입력 반응, P 키 일시정지 중 거리 정지, 홈 복귀 중 모델 정지와 캔버스 숨김, 다시 홈에서 시작, 바위·통나무·덩굴·구덩이·음식·가속 연출 렌더, 게임 화면에 안내 문구와 장애물 라벨이 없음, 모바일 가로·세로 화면 레이아웃, 콘솔 오류 없음(당시 `favicon.ico` 404는 이후 favicon 링크로 해결). 화면 저장 위치는 작업 로그에 남겼고 저장소에는 포함하지 않았습니다.

### 장애물별 통과 가능한 타이밍 창 (모델에서 측정)

점프 시작 시점을 0.04m 간격으로 훑고, 2단점프는 첫 점프 후 0.1~1.2초 사이의 입력 시점을 모두 탐색했습니다. 최대 폭이 가장 어려운 경우입니다. 가속 상태는 블록·타워·긴 장애물에 무적이라 측정하지 않았습니다. 탈진 상태의 최적 입력 시점이 탐색 상한(1.2초)에 걸려 있어 실제 창은 더 넓을 수 있습니다.

| 블록 64 | 0.18초 | 0.94초 | 0.30초 | 1.61초 |
| 타워 48 | 불가 | 0.31초 | 불가 | 0.53초 |
| 타워 64 | 불가 | 0.25초 | 불가 | 0.43초 |
| 긴 140 | 불가 | 0.74초 | 불가 | 1.26초 |
| 긴 175 | 불가 | 0.61초 | 불가 | 1.02초 |

### 알려진 점 (버그 아님, 튜닝 후보)

- 소모가 4.5/s가 되어 모든 음식을 먹어도 수입이 평균 약 4.10/s(황금 10% 기준)로 소모보다 낮습니다. 75%만 먹으면 약 3.07/s, 걸어서 먹을 수 있는 음식(약 42%)만 먹으면 약 1.71/s입니다. 그래서 체력은 항상 서서히 줄어듭니다(의도된 변경이며 테스트가 이 관계를 확인합니다).
- 장애물 사이의 빈 거리는 처음 두 개 사이가 약 18.9m, 이후 최소 약 13.1m(상한 18m 간격, 1200m 이후)입니다. 보통 속도로 약 2.2초, 가속 중에는 약 1.5초입니다. 음식은 건너뛰는 슬롯 때문에 400m 이전 약 2.4개/100m, 1600~2000m 약 1.7개/100m로 뒤로 갈수록 드뭅니다(모두 먹어도 수입 약 2.4/s → 1.6/s, 소모 4.5/s).
- (해결) 그림 용량: 게임 그림은 `game-atlas.webp` 1장(2048x1024, 17프레임, 937,292바이트)+json으로 묶였고 홈 그림 5장은 합 335,688바이트입니다. 원본 PNG는 보존됩니다. 최종 QA에서 게임 중 이미지 요청이 atlas 1장+json뿐이고 404·콘솔 오류가 없음을 확인했습니다(헤드리스 Chrome, 실제 기기 터치·FPS는 미확인).
- 참고 영상은 35초 구간만 직접 확인했고(자동 자막만 있음, 이후 구간은 재생 오류), 새 데카츠요 그림과의 세부 일치는 사람이 눈으로 확인해야 합니다.
- 장애물 그림을 폭×높이에 맞춰 늘려 그려서 비율이 달라집니다. 바위는 타워에서 가늘고 길게(원본 약 1.8:1이 약 0.3:1), 앉은 모몽가는 납작하게(원본 약 1.2:1이 약 2.8:1) 보입니다. 충돌 판정은 영향이 없습니다.
- 모바일 세로 화면에서는 게임 화면이 약 360×200px로 작습니다. 바(양끝 이미지)와 버튼은 하단 띠 안에 들어가지만 화면 자체는 작습니다. 가로 화면이 기본 권장입니다.
- 그림과 에셋을 `/assets/...` 절대 경로로 불러오므로, 앱 포장(Capacitor 등)에서 기본 경로를 바꾸면 경로 조정이 필요합니다.
- 장애물 폭이 커져도 블록 64의 보통 속도 단일 점프 창은 0.18초, 타워 64의 보통 속도 2단점프 창은 0.25초로 통과 가능합니다.

### UI v3·v4 브라우저 확인 (headless Chrome, 실제 그림)

체력 숫자와 추격 거리 수치(gap 숫자·힌트) DOM이 없음(HUD의 "달린 거리" 숫자는 의도적으로 남아 있음), 일시정지 버튼의 `paused` 클래스와 `aria-label` 전환, 플레이 중 `is-running` 클래스, 점프 버튼 `held` 클래스(앉기와 동일 스타일), 홈↔게임 전환, 게임 중 이미지 요청이 atlas 1장+json뿐임, 콘솔 오류·404 없음을 확인했습니다. 홈의 데카츠요가 모몽가보다 크고 음식은 푸딩·황금 슈크림 2개가 겹치지 않으며, HUD는 우측 상단에 버튼 아래 거리 카드 순서입니다. 시작 시 몬스터가 왼쪽 화면 일부를 채웁니다. 모바일 세로·가로에서 추격 바와 버튼은 캐릭터를 가리지 않았습니다. v4: 추격 바는 왼쪽 데카츠요 고정, 모몽가 이미지가 marker로 이동(8~92%), 점프 버튼 `held`가 손을 뗄 때 해제됨, 홈에서 황금 슈크림이 위로·모몽가가 바닥 위로·데카츠요가 더 크고 gap 칩과 터치 문구가 없음을 확인했습니다. 연출은 flat 2D(바닥 타원 그림자만)이며 몬스터는 420x280px입니다. 추격 바 이미지의 ±5° 흔들림은 CSS 코드로만 확인했고 움직임을 눈으로 본 것은 아닙니다.

## 검증하지 못한 것

- 실제 기기의 터치 입력(점프·앉기 버튼을 손으로 누르는 동작), 일반 브라우저 창에서의 사람 손 조작 느낌, 프레임 속도와 성능. headless Chrome에서 키 입력과 화면 크기 에뮬레이션만 확인했고 터치 이벤트는 보내지 않았습니다.
- 실제 사람이 플레이했을 때의 재미와 난이도. 위 수치는 시작값입니다.
- 세로 화면 배치와 작은 화면에서의 반응 시간.
- 스크립트 봇으로 3000m를 완주하는 코스 공정성 검사는 범위 밖으로 두었습니다.
- 치이카와 캐릭터를 공개 앱에 쓸 수 있는지(권리자 허가).
